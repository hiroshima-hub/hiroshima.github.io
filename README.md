# 理科・情報 授業サイト：公開と安全な運用

現行の授業原稿・表示方法は[授業スライドのスタイルガイド](docs/slide-style-guide.md)を参照してください。

2027年度開始の授業サイト用。最終更新：2026年11月10日。

## サイトの位置付け

一般公開できる教材を、生徒がログインせず閲覧するためのサイトです。生徒限定の保管場所ではありません。授業で使うことと、インターネット全体に公開することは別です。学校の外部公開・教材利用・AI制作物の利用方針に従ってください。

URLを直接配布すると目的のページへ誘導しやすくなりますが、アクセス制限にはなりません。転送・検索・複製を想定してください。URLを複雑にする、リンクを隠す、検索除外を設定するといった方法では秘密を守れません。

## 公開される範囲

- Publicリポジトリでは、HTML・Markdown原稿・PDF・画像など、置いたファイルを誰でも閲覧・複製できます。
- サイトからリンクしていないファイルも、リポジトリから見られます。
- 過去の保存内容は変更履歴に残る場合があります。通常の削除だけでは過去の情報まで消えません。
- Markdownのコメント、HTMLの非表示部分、発表者メモに秘密を書かないでください。
- 有料プランに変えるだけで生徒限定になるわけではありません。限定資料は学校指定のTeams等で扱います。
- 他人が閲覧できることと、編集できることは異なります。Publicでも、権限のない閲覧者が直接原本を書き換えられるわけではありません。

## 最初に設定・確認すること

- [ ] GitHub専用の強いパスワードを使用する。
- [ ] 個人Settings → Password and authenticationで2段階認証を設定する。
- [ ] 復旧コードを教材フォルダーとは別の安全な場所へ保管する。公開しない。
- [ ] 個人Settings → Emailsで「Keep my email addresses private」を有効にする。
- [ ] 「Block command line pushes that expose my email」も有効にする。将来Gitを使う際はnoreplyアドレスを設定する。
- [ ] メール非公開の設定は過去の履歴に遡って適用されないことを理解する。
- [ ] リポジトリSettings → Pagesの「Enforce HTTPS」と公開URLのhttpsを確認する。
- [ ] 共同編集者は必要な人だけにし、生徒に編集権限や先生のアカウントを渡さない。
- [ ] 連携アプリやブラウザー拡張機能を不用意に許可しない。
- [ ] 学校としての管理者、異動・退職時の引き継ぎ方法を決める。パスワード共有で引き継がない。

HTTPSは通信を保護しますが、閲覧者を制限するものではありません。共有PCにはパスワード・パスキーを保存せず、管理作業後はログアウトします。授業の閲覧にはGitHubへのログインは不要です。

## アップロード直前の確認

- [ ] 公開用フォルダーを、校務・成績・個人情報のフォルダーから分けている。
- [ ] 今回アップロードするファイル名と内容を確認した。
- [ ] 氏名、顔写真、名簿、成績、健康情報、連絡先、校内限定資料が入っていない。
- [ ] 未実施の試験問題、公開前の解答、指導上の内部メモが入っていない。
- [ ] パスワード、認証コード、復旧コード、APIキー、共有リンクの秘密情報が入っていない。
- [ ] 写真の位置情報、PDF等の作成者情報、コメント・メモ・添付ファイルを確認した。
- [ ] 図版・市販教材・動画・生徒作品の一般公開可否を学校の基準で確認した。
- [ ] 外部リンクを開き、意図した内容・閲覧範囲になっていることを確認した。
- [ ] Markdownの原稿全体も公開できる。画面に見える部分だけを確認して済ませていない。
- [ ] 授業スライドの内容・図・数式の正確さと、スマートフォンでの表示を確認した。

ファイル名、コメント、隠し要素、JavaScript内の文字も秘密の保管場所ではありません。ブラウザー上だけのパスワード画面は、公開ファイルの保護には使いません。

## 起こり得る事故と対策

| 事故 | 対策 |
| --- | --- |
| 校務ファイルをまとめて誤公開 | 公開用フォルダーだけから、対象を確認してアップロード |
| 原稿・履歴から解答や情報が見える | 非公開情報を公開用原稿へ入れない |
| 偽メール・パスワード使い回しによる乗っ取り | 2段階認証、ブックマークからログイン、端末更新 |
| スマートフォン紛失でログイン不能 | 復旧コードと承認済みの復旧手段を保管 |
| 知らない変更提案や外部スクリプトで改変 | 内容不明の変更・Actions・アプリ連携を採用しない |
| 外部動画の広告、内容変更、削除 | 授業前に確認し、外部サイトであることを明示 |
| 通信障害、校内の閲覧制限 | 授業前に校内端末で確認し、手元にHTML/PDFを用意 |
| 更新漏れ・別年度の上書き | 年度ごとに原稿と画像を保存し、公開後にも確認 |

公開サイトのデータを閲覧者の手元から回収することは保証できません。削除を後から行えばよい、という前提では運用しません。

## 誤公開・改ざんに気付いたら

1. 学校の情報管理担当者へ速やかに連絡し、対象URL・ファイル・気付いた日時を伝えます。
2. 拡大防止のためPagesの公開停止と、Publicリポジトリ自体の公開範囲を見直します。担当者と進めてください。
3. パスワードや認証用の鍵が漏れた場合は直ちに無効化・変更します。乗っ取りが疑われる場合はセッション・連携アプリも確認します。
4. 必要に応じてGitHubの履歴からの削除やSupportへの相談を行います。履歴書き換えは影響が大きいため、自己判断で操作を重ねないでください。
5. 正しい教材・設定を確認してから公開を再開します。

Pagesの「Unpublish site」はWebサイトを停止するだけで、Publicリポジトリのファイルや履歴は消しません。また新たな公開処理でサイトが再公開される場合があります。公開停止後の自動処理にも注意してください。

## このMarkdown表示機能について

AI、アクセス解析、入力内容の送信、外部ライブラリ・外部フォントの読み込みは組み込んでいません。公開時は同じ授業フォルダーのslides.mdを取得します。手元では先生が選択したファイルを読みます。

生徒情報を収集するフォーム・認証・提出機能はありません。独自のアクセス制限はありません。画像は相対パスのみ、外部リンクはhttpsのみを扱い、Markdown内の生のHTMLは実行しません。ただし、この構成が安全性を保証するものではなく、アカウント・設定・追加教材は別途管理が必要です。

GitHubはGitHub Pages訪問時のIPアドレスをセキュリティ目的で記録します。動画等の外部リンクへ移動した後は、そのサービスの規約・データ取扱いが適用されます。
